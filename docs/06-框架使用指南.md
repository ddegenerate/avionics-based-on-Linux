## 2. 分区配置

### 2.1 PartitionConfig 字段一览

每个分区由一个 `PartitionConfig` 结构体描述。在 `main.cpp` 中通过 `table.add({...})` 添加：

```cpp
table.add({
    partition_id,       // int: 分区唯一编号（1, 2, 3...）
    cpu_base,           // int: 起始物理核心号（如 10）
    cpu_count,          // int: 占用核心数量（1=串行，>1=并行）
    maf_slot,           // int: MAF 时间片编号（0, 1, 2...）
    slot_duration_ms,   // int: 时间片时长（毫秒）
    mode,               // PartitionMode: PARALLEL 或 SERIAL
    { /* tasks... */ }  // vector<TaskConfig>: 任务列表（空=传统模式）
});
```

### 2.2 并行分区

```cpp
// 分区 1: 并行, Core 10-11, 时间片 0, 10ms
table.add({
    1, 10, 2, 0, 10,
    PartitionMode::PARALLEL,
    { /* 任务列表 */ }
});
```

核心行为：`cpu_count > 1` + `mode = PARALLEL` → 任务按策略分配到 N 个核心，各核心在同一时间片内独立并行执行。

### 2.3 串行分区

```cpp
// 分区 3: 串行, Core 12, 时间片 2, 8ms
table.add({
    3, 12, 1, 2, 8,
    PartitionMode::SERIAL,
    {
        {10, "nav",  [&]{ ... }, 3000},
        {11, "diag", [&]{ ... }, 500, false},  // 弹性
    }
});
```

核心行为：`cpu_count = 1` → 所有任务在单个核心上顺序执行。代码路径与并行完全相同，只是核心数为 1。

### 2.4 多分区共享 MAF

两个分区占不同 `maf_slot` → 时间片不重叠，轮流使用核心：

```cpp
table.add({1, 10, 2, 0, 10,  PartitionMode::PARALLEL, {...}});  // slot 0: 0-10ms
table.add({2, 10, 2, 1, 15,  PartitionMode::PARALLEL, {...}});  // slot 1: 10-25ms
// MAF = 10 + 15 = 25ms, 两分区都在 Core 10-11 上运行
```

**注意：** 共享核心范围的分区必须使用不同的 `maf_slot`。如果两个分区同时需要 Core 10-11，就分配不同的时间片。

### 2.5 传统模式（无任务列表）

```cpp
// tasks 留空 → 自动使用传统矩阵乘法，每个核心独立跑满迭代
table.add({1, 10, 2, 0, 10});
```

传统模式下，每个核心创建一个 WorkerThread，使用 `MATRIX_SIZE=50` 的矩阵乘法负载，自适应余量保护。

## 3. 任务配置

### 3.1 TaskConfig 字段

```cpp
{
    task_id,        // int: 任务编号（唯一）
    "task_name",    // string: 可读名称（日志/统计/甘特图标注）
    workload,       // lambda: 计算负载，如 [&]{ MatrixMultiply<40>::compute(A,B,C); }
    budget_us,      // uint64_t: CPU 预算（µs），用于 slot 内安全检查
    is_critical     // bool: true=关键任务, false=弹性任务（默认 true 可省略）
}
```

### 3.2 关键任务 vs 弹性任务

| | 关键任务 | 弹性任务 |
|------|---------|---------|
| `is_critical` | `true`（默认） | `false` |
| 执行阶段 | 阶段 1：反复轮转，尽可能多跑 | 阶段 2：仅在关键任务全跑不动时接棒 |
| CSV 事件标记 | `TASK` | `ELASTIC` |
| 甘特图样式 | 实心色块 | 斜线阴影 + 半透明 |
| 超时行为 | 记录 overrun | 超时不记录（弹性本就可跳过） |

**示例：**

```cpp
{1, "sensor",   [&]{ MatrixMultiply<40>::compute(A1,B1,C1); }, 2000},          // 关键
{4, "self_test",[&]{ MatrixMultiply<10>::compute(A4,B4,C4); }, 500, false},   // 弹性
```

### 3.3 budget_us 的设置

`budget_us` 是任务的最坏情况执行时间（WCET）估算。作用：调度器用它判断"剩余时间够不够跑"。

```
needed = margin + budget_us
if (remain < needed) → skip
```

**设置原则：**
- 取实际测量 WCET 的值（宁可偏大，不可偏小）
- 太大 → 提前退出、窗口利用率降低
- 太小 → 可能跑不完、记录 overrun
- 设为 `0` → 不使用 budget 检查，只依赖 margin

**如何实测 WCET：** 先在隔离核心上用 `CLOCK_MONOTONIC` 跑 10000 次取 P99。

### 3.4 自定义计算负载

矩阵不是唯一选择。`TaskConfig::workload` 是 `std::function<void()>`，可以填入任意 `void()` 可调用对象：

```cpp
// 方式 1: 不同大小的矩阵 → 不同 WCET
{1, "light", [&]{ MatrixMultiply<20>::compute(A,B,C); }, 300},   // 20³ ≈ 8K ops
{2, "heavy", [&]{ MatrixMultiply<80>::compute(A,B,C); }, 5000},  // 80³ ≈ 512K ops

// 方式 2: 自定义循环
{3, "spin", []{ for(volatile int i=0;i<100000;i++); }, 1000},

// 方式 3: 调用外部函数
{4, "checksum", []{ crypto_checksum(data, len); }, 2000},
```

**矩阵大小与运算量对照**（近似）：

| SIZE | 浮点运算次数 | 典型耗时（隔离核） |
|------|:----------:|:-----------:|
| 10 | ~1K | ~1µs |
| 20 | ~8K | ~4µs |
| 40 | ~64K | ~30µs |
| 50 | ~125K | ~50µs |
| 60 | ~216K | ~90µs |
| 80 | ~512K | ~200µs |
| 100 | ~1M | ~400µs |

> 实际耗时受 CPU 频率、缓存状态影响，上表仅为参考。

### 3.5 声明任务矩阵

每个需要矩阵乘法的任务必须声明自己的独立矩阵并初始化：

```cpp
// 在 main.cpp 的 "步骤 A" 区域
static float A1[40][40], B1[40][40], C1[40][40];  // 声明
init_matrix(A1); init_matrix(B1);                   // 填充随机数
```

**注意：** 必须用 `static`（防止栈溢出），每个任务三块矩阵（A, B, C）。

## 4. 切换任务分配策略

任务分配策略在 `task_assigner.hpp` 中定义，在 `main.cpp` 的"创建工作线程"处调用。当前默认使用 `wcet_aware_2phase`（两阶段分配）。

### 4.1 四种内置策略

| 策略 | 函数 | 行为 | 适用场景 |
|------|------|------|---------|
| 轮询 | `round_robin(cores, n_tasks)` | 任务 0→核0, 1→核1, ...交替 | 任务 WCET 相近 |
| WCET 贪心 | `wcet_aware(cores, budgets)` | 按 budget 降序，贪心分配给负载最小的核心 | 无弹性任务 |
| WCET 两阶段 | `wcet_aware_2phase(cores, budgets, is_critical)` | 阶段1: 关键任务贪心 + 阶段2: 弹性广播到所有核心 | 有弹性任务的并行分区（默认） |
| 固定映射 | `fixed(mapping)` | 外部指定 `{核0:[0,1], 核1:[2]}` | 需要精确控制任务-核心绑定 |

### 4.2 如何切换

在 `main.cpp` 中找到这一行（约第 344 行）：

```cpp
auto assignment = task_assign::wcet_aware_2phase(
    p.cpu_count, budgets, is_critical);
```

改为其他策略：

```cpp
// 切换为轮询分配
auto assignment = task_assign::round_robin(p.cpu_count, p.tasks.size());

// 切换为 WCET 贪心（不区分关键/弹性，全部一起贪心）
auto assignment = task_assign::wcet_aware(p.cpu_count, budgets);

// 切换为固定映射
auto assignment = task_assign::fixed({{0, 2}, {1, 3, 4}}); // 核0: task0+2, 核1: task1+3+4
```

### 4.3 如何编写新的分配策略

在 `task_assigner.hpp` 的 `task_assign` 命名空间中添加新函数：

```cpp
// 策略 5: 按任务名称排序后分配
inline Assignment my_custom(int num_cores,
                             const std::vector<uint64_t>& task_budgets,
                             const std::vector<std::string>& task_names) {
    Assignment result(num_cores);
    // ... 你的分配逻辑 ...
    return result;
}
```

函数签名自由设计，只要返回 `Assignment`（即 `vector<vector<int>>`）即可。然后在 `main.cpp` 中调用。

## 5. 切换余量计算策略

### 5.1 三种策略

| 策略 | 枚举值 | 行为 | 适用场景 |
|------|--------|------|---------|
| EWMA + 2σ | `EWMA_2SIGMA`（默认） | 指数加权移动平均 + 2倍标准差上界 | 通用，负载有波动 |
| last × 1.2 | `LAST_TIMES_12` | 上次执行时间 × 6/5 | 向后兼容旧版 |
| 固定值 | `FIXED` | 使用 `SLOT_MARGIN_INIT_US`（2000µs） | 负载极稳定 |

### 5.2 如何切换

在 `main.cpp` 顶部（约第 153 行）：

```cpp
constexpr WorkerThread::MarginStrategy MARGIN_STRATEGY =
    WorkerThread::MarginStrategy::EWMA_2SIGMA;
    // 改为:
    // WorkerThread::MarginStrategy::LAST_TIMES_12;
    // WorkerThread::MarginStrategy::FIXED;
```

### 5.3 EWMA 参数调整

在 `worker_thread.hpp` 中修改：

```cpp
// === EWMA 参数 ===
static constexpr double EWMA_ALPHA      = 0.3;   // 平滑系数 (0~1)
static constexpr double SAFETY_K        = 2.0;   // σ 倍数 (2.0 ≈ 95% 置信)
static constexpr uint64_t MIN_MARGIN_US = 500;   // 最小余量保护 (µs)
```

| 参数 | 作用 | 调大效果 | 调小效果 |
|------|------|---------|---------|
| `EWMA_ALPHA` | 新数据的权重 | 更快响应变化，但更敏感 | 更平滑，但对趋势变化迟钝 |
| `SAFETY_K` | σ 的置信倍数 | k=3 → 99.7% 置信，更安全但更多浪费 | k=1 → 68% 置信，更激进 |
| `MIN_MARGIN_US` | 余量底线 | 更安全，浪费更多 | 更高利用率，但抖动时可能 overrun |

**推荐范围：** `α = 0.2~0.4`, `k = 1.5~3.0`, `MIN = 300~1000`。

### 5.4 last × 1.2 参数调整

在 `worker_thread.hpp` 中：

```cpp
static constexpr uint64_t SLOT_MARGIN_INIT_US = 2000;  // 首次迭代的固定余量
static constexpr uint64_t MARGIN_FACTOR_NUM   = 6;     // 分子
static constexpr uint64_t MARGIN_FACTOR_DEN   = 5;     // 分母 → ×6/5 = ×1.2
```

改为 `8/5 = ×1.6` 可提供更大的安全缓冲，但吞吐量下降。

### 5.5 固定值策略参数

固定值用的是 `m_fixed_margin_us`，初始化为 `SLOT_MARGIN_INIT_US`（2000µs）。如需修改此策略的默认值，在 `WorkerThread` 构造函数或 `worker_thread.cpp` 中修改 `m_fixed_margin_us` 的初始值。


## 9. 常见配置场景速查

### 场景 A：我想加一个新分区

1. 在 `main.cpp` 配置区添加 `table.add({...})`
2. 声明该分区所有任务的矩阵（如有）
3. 确保 `maf_slot` 不与其他分区冲突（或故意共享 slot 实现并行执行）
4. 确保核心范围在 cgroups 隔离区内

### 场景 B：我想试一种新的调度算法

两种改法：
- **只改任务→核心分配规则** → 在 `task_assigner.hpp` 加新函数，`main.cpp` 换调用
- **改 slot 内任务执行顺序** → 修改 `worker_thread.cpp` 中的 `run_task_loop()` 函数，替换阶段的遍历逻辑

### 场景 C：我想比较两种余量策略

1. 用 `EWMA_2SIGMA` 跑一次 → 保存 `trace_log.csv`
2. 改 `MARGIN_STRATEGY = LAST_TIMES_12`，重新编译
3. 再跑一次 → 保存另一个 CSV
4. 分别用 `plot_slots.py` 画甘特图，对比空闲比例和 overrun 次数

### 场景 D：我想让任务跑得更满

1. 收紧各任务的 `budget_us`（使其更接近真实 WCET）
2. 降低 `MIN_MARGIN_US`（如从 500 → 300）
3. 减小 `EWMA_ALPHA`（如 0.3 → 0.2，对新数据更平滑）
4. 重新编译运行 → 观察 slot 时长是否更接近配置值、overrun 是否仍为 0

## 10. 修改后的 checklist

每次修改配置后，按顺序执行：

```bash
# 1. 重新编译
cd src/
g++ -std=c++17 -O2 -pthread main.cpp maf_clock.cpp worker_thread.cpp -o avionics_parallel_v8

# 2. 确保在隔离区内
sudo sh -c "echo \$\$ > /sys/fs/cgroup/avionics_partition/cgroup.procs"

# 3. 运行
sudo ./avionics_parallel_v8

# 4. 生成甘特图验证
python3 plot_slots.py trace_log.csv --max-cycles 10 --detail-cycles 3
```

关注终端输出中的三个关键指标：
- `overrun: 0` — 没有超时（如果非零，说明 budget 或 margin 设置有问题）
- `yields > 0` — 自适应停手在工作
- `avg_margin` — 平均余量，越小利用率越高

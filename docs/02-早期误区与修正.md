# 早期误区与修正 — 四层分区实验的认知迭代

---

## 1. 背景：从四层分区到分区调度

在构建并行分区实验框架之前，我们首先完成了涵盖**时间、核心、内存、缓存**的四层硬件与系统级隔离实验。

> **核心认知：** cgroups 做的四层分区，其实是在 Linux 环境下划分出了一片用来进行分区的"场地"。实际的航电分区，是在这块被圈出来的"纯净场地"上建立的严格执行计划。


---

## 2. 误区一：重新定位 cgroups 的作用

### 2.1 原有误区

最初认为必须通过 cgroups 直接将不同的分区硬性绑定到完全独立的核心上。例如：分区 1 独占 Core 10-11，分区 2 独占 Core 12-13，两者永不交叉。

### 2.2 实际情况

在进行串行分区实验时发现，**时间分区的本质是"同一个核心在不同的时间片被不同的分区时间复用"**。因此，不同的分区未必需要完全隔离在不同的物理核上。

### 2.3 修正结论

- cgroups (cpuset) 的真正作用是**从庞杂的 Linux 系统中圈出一块不受后台干扰的"干净自留地"**
- 它不是用于定义时间分区的执行边界——时间分区由 MAF 时钟和 Slot 机制负责
- 一套纯净的 cgroup 可以容纳多个分区轮流在其上运行（时间片驱轮转）

---

## 3. 误区二：SCHED_DEADLINE 调度器的局限性

### 3.1 原有误区

希望继续使用基于 CBS（恒定带宽服务器）算法的 `SCHED_DEADLINE` 来管理并行分区。CBS 的优点在于它能自动进行带宽核算：如果线程超出预算，内核会硬性截断。

### 3.2 实际情况：Catch-22 困境

在并行分区场景下，当尝试将分区内的任务细粒度地解绑到特定单核上并发执行时，遭遇了 Linux 内核的一个设计约束：

```
cgroup cpuset partition (root) → 独立 Root Domain {10, 11}
SCHED_DEADLINE 线程亲和性     → 必须覆盖整个 Root Domain
pthread_setaffinity_np(10)     → EBUSY ❌
```

**CBS 需要在整个 Root Domain 范围内追踪和限制带宽消耗。** 如果允许 DL 线程只绑定到子集核心，CBS 的全局带宽视图就会失效。这是 CBS 算法正确性的前提。

### 3.3 两种替代方案的对决

| 维度 | SCHED_DEADLINE | SCHED_FIFO | 分析 |
|------|:---:|:---:|------|
| 单核绑定 | ❌ EBUSY | ✅ 成功 | **选择 FIFO 的核心原因** |
| RT 优先级 | ✅ | ✅ (prio=99) | 两者都不会被 CFS 抢占 |
| 硬节流 | ✅ CBS | ❌ 无 | FIFO 的短板 |
| 不截断迭代 | ❌ CBS 会截断 | ✅ 自适应停手 | FIFO 的优势 |

### 3.4 修正方案

选择 **`SCHED_FIFO(99)` + 全局时钟对齐 (`TIMER_ABSTIME`)** 的方案来接管多核并行调度。

SCHED_FIFO 虽然缺少 CBS 的带宽核算，但通过 **MAF 时钟 + EWMA 自适应余量** 在用户态进行替代。更重要的是：**自愿停手带来的"干净边界"比 CBS 的"硬截断"更适合航电分区**——截断会留下半成品迭代，而自愿停手保证每次边界都是完整的工作单元。

---

## 4. 对"SCHED_DEADLINE 能不能实现并行分区"的回答

**能，但有前提。** 如果接受"一个 DL 线程覆盖整个 Root Domain 的所有核心"（即不绑单核），SCHED_DEADLINE 的 CBS 能保证带宽隔离。

**但这个前提对航电分区来说存在一些问题：**
- Linux自身的调度均衡强行起作用，后续没法用自己设置的调度算法
- 失去了核心级别的精确控制——而这是航电分区对确定性要求的核心

---

## 5. 从误区到正确架构

这两个误区的修正，直接塑造了最终框架的架构选择：

| 早期认知 | 修正后的认知 | 对应模块 |
|---------|------------|---------|
| cgroups 直接绑死分区 | cgroups 圈场地，MAF 管时间 | `setup_core.sh` + `MafClock` |
| SCHED_DEADLINE 管理一切 | SCHED_FIFO + 用户态余量 | `scheduler.hpp` + `WorkerThread::calculate_margin()` |
| 内核保证不越界 | 自适应主动停手 + 双层接力 | `WorkerThread::run_task_loop()` |
